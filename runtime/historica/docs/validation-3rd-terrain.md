数据：6 景（1993、2003 单景；2012、2024 各 2 景同日双轨），传输 81.7 MB，实测 584.5 s，无暂停。

## 4. 四个问题的答案

### 4.1 选景器会不会退化到“随便挑云量最低的那景”，四期季节全乱？

**部分退化：选景器没有季节约束，但没有退化到“只认云量”。**

- 打分仍是四项（覆盖 40% / 云量 25% / 太阳高度 15% / 日期离散 20%），没有“季节一致”这一项；
- 实际不是“云量最低就选”：1993 期候选里 `1993-12-27` 云量 1.0%（比入选的 4.0% 更低），但太阳高度只有 31.4°，综合分 0.975 < 0.986，所以选了 10-08；2012 期候选里 `2013-04-14` 云量 0.0%，但综合分 0.872 < 0.882，仍选 09-29；
- 结果确实“季节散”：2003 期落在冬季（2 月），其余三期在秋季（9–10 月），日序最大差 250 天、标准差 101 天。

结论：**“四期季节全乱”的程度是 1/4 期错季**，不是全部乱；但“同一季节”这条预期**不成立**——插件从不为季节付代价，只按四项打分，且会在报告与图面如实标出实际日期。若用户需要同季，只能手动 `--prefer-date`，插件不会自动做。

### 4.2 湿润气候下可读覆盖能到多少？低于 50% 时是如实标缺测还是偷偷拉别的日期？

- 本轮四期可读 **99.4 / 97.8 / 98.1 / 98.7%**，全部远高于 50%，**没有触发缺测分支**；
- 没有跨季补洞：2012、2024 的第二景与第一景**同日**（`span_days = 0`），metadata 里两行日期完全相同；
- 缺测构成见第 3 节：填充 0、QA 云影 5.3–20.8 km²、薄卷云仅 0.08 km²。

需要说明的是：这个“高可读”是**选景成功的结果**，不是湿润区本身容易。四期候选分别有 11 / 16 / 14 / 35 景，低云窗口在 2 月、4 月、6 月、9 月、10 月、11 月都出现过——插件是在全年范围内挑“当下最清楚的一天”，因此湿润区也能拿到 98%。代价就是 4.1 的季节不一致。

“低于 50% 如实标注”的路径本轮未被触发；该机制在另外两轮已有实证：延平 1993 缺测 659 km²（区界覆盖 75.2%）、珠三角 2012 可读 78.8%，都在图面标了斜纹与面积，没有补日期。

### 4.3 薄卷云筛查命中率是否合理？

| 轮次 | 命中 | 占区界 |
|---|---|---|
| 延平 2003（山地、多云） | 309.9 km² | 11.69% |
| 珠三角 2024（沿海、低云） | 77 px | ≈0.00% |
| 花溪 2024（高原、极低云） | 205 px（0.08 km²） | 0.008% |
| 花溪 1993 / 2003 / 2012 | 0 / 0 / 0 | 0 |

结论：**合理但样本偏弱**。命中量与“选进来的景有多干净”强相关：花溪四期景云量 0–4%，薄卷云本就不多；延平 2003 是主动挑了一个有薄卷云的场景来标定阈值，才有 310 km²。三种地形的量级差异（310 km² → 0.08 km² → 0）说明规则不是乱扣，但它**无法证明在“必须用多云景”的湿润区还能不能扣准**——本轮没有那种场景。

### 4.4 预估误差：并发探针 + 2 条校准记录表现如何？落不落在区间内？

| 项 | 值 |
|---|---|
| 样本 | 本轮探针 5 轮 + 校准 2 条（0.384 / 0.118），共 7 |
| 点估计 | 0.319 MB/s → **436 s**（7.3 min） |
| 区间 | 0.225–0.411 MB/s → **378.6–542.5 s**（6.3–9.0 min） |
| 实测 | **584.5 s**（9.7 min），无暂停 |
| 点误差 | **+34.0%** |
| 区间 | **未覆盖**（实测超上界 7.7%） |
| 探针/实测净吞吐 | 0.319 / 0.202 = **1.58×** |
| 看门狗 | 20 块，0.132–2.093 MB/s，中位 0.232，阈值 0.113，**未触发** |

原因：探针那 1–2 分钟正好落在快窗口（0.297–0.424），随后的下载时段回落到 0.132–0.232；本轮**没有**触发暂停，所以 as-run 就是冷启动等价，误差不能用“暂停”解释。

结论：**部分失效**——点估计偏乐观 34%，区间偏窄 7.7%。探针解决了“单流低估”的形态问题（延平 −80% → 本轮 +34%），但解决不了“测速时段 ≠ 下载时段”。看门狗兜住了“慢到必须停”的情况（阈值 0.113，最低块 0.132 未触发），但没有兜住“整体偏慢 30%”这种中等偏差。

## 5. 判断：这套规则在第三种地形上是否仍成立

**结论：部分成立。**

| 规则 | 判断 | 证据 |
|---|---|---|
| 范围解析与真实区界 | **成立** | `贵阳市花溪区` → DataV 961.55 km²，格网 30 m，无回退 |
| 几何覆盖 ≠ 可读覆盖 | **成立** | 四期几何覆盖都是 100%，可读 97.8–99.4%，报告两列并列 |
| 缺测如实标注、不跨季补洞 | **成立（未被压力测试）** | 本轮无 <50% 期；2012/2024 双景均同日，`span_days=0` |
| 薄卷云筛查 | **成立（样本弱）** | 0.08 km²，量级合理；但四期景太干净，未验证多云场景 |
| 选景季节一致性 | **不成立** | 没有季节项；2003 落在 2 月，日序最大差 250 天 |
| 区间估算 | **部分不成立** | 区间漏掉实测 7.7%，点估计偏乐观 34% |
| 看门狗 | **成立（未被触发）** | 最低 0.132 > 阈值 0.113，全程未暂停；珠三角轮已验证会停 |

**哪一条真正失效**：⑸“选景应保持同一季节”这条**规则本身不存在**——插件只按四项打分，湿润区会自然滑到“全年找最清楚的一天”。这不是 bug，但必须在使用说明里讲清楚：需要同季就手动 `--prefer-date`，否则四期可能是“秋/冬/秋/秋”。

**附带发现**：配准 9 窗口锁定 7、未锁定 2，最小置信比 0.079（低于 0.2 判“未锁定”）。湿润区植被覆盖高、纹理均匀，梯度相关比山地弱；报告已把未锁定窗口单列，没有用零位移糊过去。

### 6.2 四个问题重答（v1.1 口径）

1. **会不会退化到“随便挑云量最低”、季节全乱？**
   **不会了。** 四期落在 10-08 / 11-13 / 11-19 / 10-29，全部 10–11 月，日序标准差 16.2 天、最大差 42 天。调整不是“只挑云量最低”：1993 期候选里 12-27 云量 1.0%（低于入选的 4.0%），但不在窗口；窗口内按覆盖/云量/太阳高度/季节一致综合选。代价见 6.1。

2. **湿润气候可读覆盖能到多少？低于 50% 时会不会偷偷拉别日期？**
   可读 **99.4 / 93.8 / 92.0 / 98.7%**，无一低于 50%。缺测构成：QA 云/云影为主（2003 59.3 km²、2012 77.0 km²），填充 0，薄卷云区界内 0.01%（2024）。2012 与 2024 都是单景或**同日双轨**，`span_days = 0`，没有跨日期补洞。
   需要如实说的一点：2012 期取的是 **2011-11-19**（目标 2012，仍在 ±1 年窗口内）——这是“同季优先”的直接后果，不是错标年份。

3. **薄卷云筛查在这种气候里命中率是否合理（第三样本）？**
   本轮命中 **2024 期 295 px**（区界内 0.01%，格网口径 0.2 km²）；1993/2003/2012 为 0。量级与珠三角（77 px）接近，仍属**合理但样本弱**：同季窗口把景都挑干净了，没有出现“必须用多云景”的压力场景。

4. **预估误差：并发探针 + 2 条校准（0.384 / 0.118）表现如何？区间是否覆盖实测？**

| 项 | v1.0（无季节锁） | v1.1（同季） |
|---|---|---|
| 样本 | 探针 5 轮 + 校准 2 条 = 7 | 探针 5 轮 + 校准 3 条 = 8（分块样本本轮开工前为 0） |
| 点估计 | 0.319 MB/s → 436 s | **0.191 MB/s → 539 s** |
| 区间 | p10–p90：378.6–542.5 s | **p5–p95：348–704 s** |
| 实测 | 584.5 s | **600 s**（无暂停） |
| 点误差 | +34.0% | **+11.2%** |
| 区间覆盖实测 | 否（超上界 7.7%） | **是** |
| 探针 / 实测净吞吐 | 0.319 / 0.202 = 1.58× | 0.18 / 0.165 = **1.09×** |
| 看门狗 | 20 块 0.132–2.093，阈值 0.113，未触发 | 20 块 0.103–1.424（中位 0.162），阈值 0.067，未触发 |

结论：**区间覆盖实测、点误差从 +34% 收到 +11.2%**。改进主要来自“p5–p95 + 探针本身更接近下载时段”，而不是分块样本——本轮开工前校准表里的历史记录还没有 `block_speeds_mbps`，分块样本要到**下一轮**才真正进池。这一点必须写明，不能把功劳记在还没生效的机制上。

### 6.3 判断：“看得懂但覆盖更差”是不是真的，代价多大

**是，但代价可量化、且没有击穿验收线。**

- 收益：季节离散度从 std 101 天 / 最大差 250 天，降到 **16.2 天 / 42 天**；四期落在同一物候区，色调与植被状态可比。
- 代价：平均可读 **−2.5 pp**，最差一期 **−6.1 pp**（2012）；没有一期低于 92%，离 70% 验收线还有 22 pp 余量。
- 如果某期窗口内真的没有低云景，插件会回退并标 `cross_season: true` + 跨季天数 + 放开窗口的推断收益——本轮没有触发，但代码路径与报告口径已经在 `cross_season` 分支里备好。
- 所以这道锁不是“无脑变差”：它把“看得懂”的代价压在了 **2–6 个百分点**；在花溪这种湿润区，这个代价换来的季节一致性是值得的。真正需要警惕的是“窗口内只有 60–70% 覆盖”的情形，那时报告会明确提示，用户可自行用 `--season-window 0` 重跑。
