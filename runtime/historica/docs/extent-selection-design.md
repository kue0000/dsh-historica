## 0. 输入归一化

四种范围输入统一落成一个 `AOIRecord`：`geometry`（WGS84 的 Polygon/MultiPolygon，**保留孔洞**）、`bbox`、`area_km2`（椭球面积，pyproj Geod）、`perimeter_km`、`mrr`（最小外接旋转矩形）、`source`、`precision`、`digest`。后续所有步骤只读这个记录，不再区分来源。

- **行政区名**：先按「省 > 市 > 区」拆词，在 DataV `all.json` 扁平索引里逐级匹配 `adcode`，再取 `{adcode}.json` 单面边界，最后做 GCJ-02→WGS84 迭代反算。反算残余 **1–2 m（实测：与 GADM 叠合 96.4%，差值主要来自坐标系偏移）**。回退顺序固定为 **DataV → GADM 2 → GADM 3 → 报错**，不允许静默降级：今日实测 GADM 4.1 的 `CHN_3` 里**没有「延平区」这一要素**（被标成 Nanping/Nanping），只靠 GADM 会拿到市级面。元数据必须写「用了哪个源、精度多少、匹配到的全名」。
- **bbox**：四数 `W,S,E,N`，`W≥E` 或超经纬度范围直接报错（实测：延平 `117.848–118.673E, 26.243–26.866N`）。
- **矢量**：GeoJSON/Shapefile/ZIP/KML/WKT，只取面要素，**假定 WGS84**；`.prj` 不解析（经验值未验证，存在被误当 WGS84 的风险）。多部件合并为 MultiPolygon，孔洞保留。
- **HTML 框选**：导出 bbox 或 GeoJSON，等同前两条路径。
- **MRR**：凸包 + 0.5° 旋转扫描（经验值未验证；对 2,653 km² 的区界开销可忽略）。
- 失败降级：边界拿不到就报错退出，**绝不拿「名称的外接矩形」冒充行政区**。面积合理性检查：若回退到上级行政区导致面积 > 期望值 2 倍（`boundary.area_sanity_ratio`），报错。

## 1. 面积口径

三个数必须同时存在于元数据，且不许混用：

| 口径 | 延平 1993 实测 | 用途 |
|---|---|---|
| 外接矩形 bbox | 5,675.8 km²（约 83×68 km，实测） | **只算窗口与成本** |
| 真实区界 | 2,653 km²（DataV 350702） | **展示、覆盖率、缺失面积** |
| 图幅内可读像元 | 区界 ∩ 有效像元（实测 1993/2003/2012/2024 = 49.1/64.0/93.9/99.4%） | 单列，不参与选景打分，但进验收闸门 |

规则：**对外展示与覆盖率一律用真实区界；外接矩形只用于算窗口与成本**。原因很直接：延平矩形是区界的 **2.14 倍（实测）**，用矩形算成本会高估一倍，用矩形算覆盖率会把区界外四角算成「缺失」，把 75.2% 压低成 69.5%。

**可读覆盖 ≠ 几何覆盖**：2003 四景几何 100%，但按 `QA_PIXEL` bit1–4 去云去影后，区内只剩 64.0%，缺 954.6 km²；1993 几何 75.2%，可读仅 49.1%（无影像 659.1 km² + 云/阴影/暗像元 690.1 km²）。因此验收闸门必须用第三口径，不能只看「100%」。

判据（默认，全部可配置）：覆盖率 **≥95% 视为满覆盖**；**85–95% 为可接受，但图上必须标缺失面积**；**<85% 必须用户显式确认，或自动降级到多轨/跨季**。延平 1993 是 75.2%，落在第三档，所以方案 A 是「用户已确认的例外」，报告里要写明确认。

## 2. 选景：从候选到组合

**分组**：同日（`date_group_span_days=0`，实测）→ 同组内按 WRS-2 `path/row` 去重 → 年份窗口默认 ±1（`year_window`，实测：延平 1993 的查询窗是 1992–1994，候选 68 组）。

**四项打分**（权重实测固定）：

```
score = 0.40·C + 0.25·(1 − cloud/100) + 0.15·(1 − |sun − 45°|/90) + 0.20·D
D = max(0, 1 − |Δyear| / (half_width + 1))
```

`C` 为组足迹并集 ∩ 区界的面积比；`cloud` 取组内最大值、`sun` 取组内最小值（最坏情况，实测口径）。覆盖 <60% 时分数乘 0.5（经验值未验证）。

数值复算（实测，与今日排序一致）：

| 候选 | C | 云% | 太阳高度 | D | 得分 |
|---|---|---|---|---|---|
| 延平 1993-12-26 | 0.752 | 4.0 | 31.4° | 1.0 | **0.868** |
| 延平 1993-05-09 | 0.766 | 15.0 | 59.6° | 1.0 | 0.844 |
| 延平 1994-05-12 | 0.791 | 0.0 | 59.2° | 0.5 | 0.793 |
| 珠三角 1993-09-03 | 0.875 | 1.0 | 55.3° | 1.0 | **0.930** |

例：1993-12-26 = `0.4×0.752 + 0.25×0.96 + 0.15×(1−13.6/90) + 0.2×1 = 0.3008+0.2400+0.1273+0.2000 = 0.868`。

**组合阶梯**：单景 → 双轨同日 → 双轨异日/多日 → 多轨（≥3 景）。触发条件：单日覆盖 <`target_coverage`(99.5%)，且混合方案增益 ≥ **5 个百分点**（`mixed_gain_pp`，经验值未验证），且跨度 ≤32 天、景数 ≤4。代价按「覆盖增益 / 季节离散 / 流量」三项并列写进候选排名，不隐藏。

**硬约束**：同组最大日期跨度 ≤ **30 天**（`max_date_span_days`，**经验值未验证**；依据是今日实测跨度 1 天（延平 2004）、9 天（延平 2013）、16 天与 23 天（珠三角），30 天约等于一个物候月）。超限必须在报告里标「跨季」，且**图上不允许只写年份**，必须写实际成像日期与跨度天数。

**什么时候宁可缺角**：若达到 ≥95% 需要跨度 >30 天，或必须引入云量 >20% 的景（`crossseason_cloud_max`，实测阈值），则优先「缺角同季」。延平 1993 正是此例：32 天窗内最佳混合方案达不到 80.2%（75.2%+5pp）的门槛，所以保留同日双轨、接受 75.2%。

## 3. 窗口与读取

步骤：目标 bbox ∩ 场景足迹 → 取该交集在 WGS84 下的 bbox → 投影到**该景原生 CRS** → 裁到影像范围 → 按 **256×256 块**向外取整，再外扩 **1 块 halo** → 记录 `(col_off, row_off, width, height)`。

**必须逐景读 `proj:epsg`，不能写死 UTM 带**。今日实测：延平四期所选 14 景全部是 **EPSG:32650**；而珠三角 122/044 是 **32649**、121/044 是 **32650**。同一 AOI、相邻 path 落在不同带，是常态。STAC 新版还会用 `proj:code`（`"EPSG:32650"`）代替 `proj:epsg`，两者都要认。

**重叠与飞地**：相邻 path 重叠约 **7%（WRS-2 规范值，经验值未验证于本数据集）**。融合只做一种：**曼哈顿距离到边界的线性羽化，默认 2 km**。不选硬切（缝线可见）、不选加权平均（12 m 级绝对偏移下会出鬼影），羽化单遍即可且无鬼影。飞地/孔洞按 MultiPolygon 逐环掩膜，孔洞内不出图、计入缺失面积。

**为什么只读窗口**：单波段整景 **86.4 MB（实测，Content-Range）**；延平单景四波段窗口合计 **17.1 MB 级别**；压缩比 **0.509（实测，用全文件字节数 / 未压缩字节数推算，不是常数）**。四期 14 景实测原始 568.9 MB、传输 289.6 MB，对比整景口径约 **4.8 GB**，约 **16.6×** 降幅。

**GSD 档位**（默认 30 m，实测）：

| 档位 | 像素量 | 传输量 | 判读能力 |
|---|---|---|---|
| 30 m 原始 | 1.00 | 1.00 | 建成区、道路、水库、大型厂房 |
| 60 m（overview 2） | 0.25 | 0.25 | 仅建成区轮廓，道路断线 |
| 90 m（overview 3） | 0.111 | 0.111 | 仅城市扩张方向，不可判读地块 |

## 4. 成本模型与预估

```
传输 MB = Σ_scene( 窗口px × 波段数 × 2B × 压缩比 × 1.25 ) × K_overlap
耗时 s  = 传输MB / 实测吞吐 + 4.8 s × 波段数 × 景数 + 1.2 s/Mpx × 处理像素
```

`K_overlap` 的用法要说清：今日的 Σ 是**逐景窗口求和**，重叠已被各景窗口自然计入，取 **1.0**；只有在「按单个 bbox 窗口 × 景数」外推时才乘 **1.5（经验值未验证）**，不可重复计。

**测速协议**：对签名 COG 做 **8 MB Range GET**，取 **3 次中位数**（`probe_samples=3`）；任一次失败降级到 `fallback_speed_mbps=0.21` 并在报告标「未测速」。今日 11 次实测在 **0.045–0.85 MB/s** 间波动，因此必须同时给 0.05/0.1/0.2/0.5/1.0 MB/s 的敏感性表（自动生成）。

**误差回写**：每次运行把 `(预估, 实测, 误差率)` 追加进 `cache/calibration.json`；存的是**净传输吞吐**（`传输MB / (实测总时长 − 打开 − 处理)`），下次预估再加回固定开销，避免重复计。今日延平全链路：预估 4998 s、实测 1227 s、误差 **−75.4%**，净吞吐 **0.384 MB/s**；单次 8 MB 探针当时只测到 0.064 MB/s，是明显低值。所以**不能把单次探针当点估计**：闸门应取「探针 × 敏感性区间」与「最近 5 次校准中位数」的较大者作为悲观值。今日三个旧结论被推翻：①单次探针可当点估计（否，本例偏差 −75%）；②几何覆盖 100% 即可交付（否，可读仅 64–94%）；③云量元数据够用（否，冬季山地云影把 2003 可读压到 64%，而整景云量只有 15%）。30 天跨度阈值未被推翻，但实测显示可读性更多由云/阴影决定，而不是跨度。

## 5. 停止与确认闸门

| 条件 | 动作 |
|---|---|
| 预估 <10 min 且覆盖 ≥95% 且景数 ≤2 且同季 | 自动放行 |
| 预估 >10 min | 停下等确认 |
| 覆盖 <85% | 停下等确认（必须给缺失 km² 与备选） |
| **可读覆盖 <70%** | 停下等确认（SLC-off/云影导致时给换季方案，不靠加景硬补） |
| 景数 ≥4（多轨） | 停下等确认（给流量账） |
| 跨季或跨度 >30 天 | 停下等确认（图上强制标跨季） |
| 实测吞吐/预估 >1.3 倍 | 暂停，重估剩余期数后再问 |

今日实际：延平预估 67–108 min，实测 20.5 min，用户预授权放行。

## 6. 失败与降级路径

- **STAC 不可达/限流**：重试 5 次（指数退避）→ 裸 HTTP `/search` → 仍 429 则改用集合级 SAS token（`/sas/v1/token/<collection>`，一次覆盖整桶）；仍失败才报错，不静默用旧缓存冒充新查询。
- **某景缺波段**：整景丢弃并重排候选；若该期因此跌破 85%，按闸门停下来问。
- **云量全超阈值**：先在 ±1 年窗口内降云量重排；仍无则把阈值放宽到 30% 并显式标记「降级」，不偷偷放宽。
- **跨轨缝无可用景**：输出「缺角同季」，报告写缺失 km² 与两个备选（B 满覆盖跨季、C 单轨缺角）的覆盖率与季节代价。
- **吞吐骤降**：第 1 期后复测，超 1.3 倍即暂停并重估，避免「默默跑一小时」。
- 所有失败都必须落在报告的「这是我能给的最好结果，以及为什么」一节，包含：选了什么、放弃了什么、缺多少、跨度多少天。

## 7. 三个工作示例

**延平 1993（缺角同季，方案 A）**：68 组候选，12-26 双轨得分 0.868 居首；32 天窗内混合方案达不到 80.2% 门槛 → 保留单日。几何覆盖 75.2%、无影像 659 km²、2 景、窗口 7.73 M 像素，预估 11.3 min、实测 1.7 min；可读仅 49.1%（另有 690 km² 被云/阴影/暗像元掩掉）。备选 B（满覆盖跨季）与 C（单轨缺角）只进排名。

**延平 2004（满覆盖 4 景）**：单日最佳 2004-10-05 覆盖 85.3%、得分 0.931，但未达 99.5%；混合方案 2003-01-12~13 跨 1 天、4 景、覆盖 100%，增益 14.7pp > 5pp → 选混合。**实际成像跨到 2003 年**，报告与图面必须写真实日期。预估 9.7 min（未实跑）。全链路验证改用 2003 目标：实际成像 2002-02-02~18、4 景、几何 100%，但可读仅 64.0%，预估 15.2 min、实测 6.9 min。

**珠三角核心 1993（跨年）**：单日最佳 1993-09-03 覆盖 87.5%、得分 0.930；混合方案 1992-01-13~29 跨 16 天、4 景、覆盖 100% → 选混合。代价是**跨年 1 年 + 冬季物候**，报告必须标「跨季」，且 1992 与 1993 传感器同为 TM，辐射代次一致（这一点比跨传感器拼接稍好）。预估 8.4 min/期，四期合计 26.3–42.7 min。

## 8. 这套逻辑会在哪里失效

1. **边界精度不足**：DataV 是 GCJ-02 反算的示意边界，与 GADM 仅 96.4% 叠合；沿岸、填海区、飞地会把「缺失」算错几十平方公里。
2. **面积合理性检查可能误伤**：面积阈值 2 倍是经验值，遇到真正狭长或跨县合并的区界会误报。
3. **30 天「同季」阈值未验证**：南方 30 天物候差异可接受，北方/高原可能已跨季。
4. **1 块 halo 抬高 15–30% 成本**，启用后时间上调。
5. **矩形窗口仍高估流量**：旋转足迹下窗口约为贡献面积 2.5 倍（实测），只能逼近不能精确。
6. **±1 年窗口会悄悄换年**：延平「2025」实际选 2024-02/03，珠三角「1993」实际选 1992-01；只写年份就是误导，必须写实际日期。
7. **吞吐方差 18 倍（实测 0.045–0.85 MB/s）**：任何单次预估都可能偏离 1 小时以上，敏感性表比点估计更可信。
8. **云量元数据 ≠ 实际掩膜**：`eo:cloud_cover` 是整景统计，AOI 内实际云量可能显著不同，覆盖率与「可读像元」会打架。
9. **签名接口会限流**：逐文件 `/sas/v1/sign` 约 30 次/分后返回 429；改用集合级 token（实测一次覆盖整桶）。
10. **传感器缺口与地形阴影被当成缺失**：2012 LE07 的 SLC-off 楔形带补不齐；冬季 bit4 把地形阴影当云影（1993 掩掉 690 km²），只能换季或接受。
