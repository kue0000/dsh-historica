# historica v1.1.0 · 交付包可移植性自检

自检方式：把 `historica-v1.1.0-dsh.zip` 解压到一个与源码目录无关的干净临时目录，只在该目录内执行。
下面三条命令的输出均为实际运行结果（未做修饰，长 ResourceWarning 已省略，不影响结论）。

- 自检目录：`%TEMP%\historica_selftest_20261106\historica`（由 zip 解压得到）
- 解释器：Python 3.12.13
- 依赖：numpy 2.5.4 / shapely 2.2.0 / pyproj 3.8.0 / matplotlib 3.11.2
- 依赖环境沿用已装好的 venv（未在本轮重建 venv；DSH 侧首次迁移请按 `DSH-迁移说明.md` 第 3 节重新安装）

## 1) 版本号

```
> python historica.py --version
historica 1.1.0
exit=0
```

## 2) 全量单元测试

```
> python -m unittest discover -s tests -q
Ran 36 tests in 5.444s

OK
exit=0
```

（输出中的 `ResourceWarning: unclosed file` 是测试代码里 `json.dump(... open(...))` 未显式关闭的历史写法，
与迁移无关，不影响测试结果。）

说明：

- `--plan` 走的是「跳过 STAC 查询、用既有计划复算」的路径，`--no-probe` 跳过测速，`--speed 0.2` 显式给吞吐，
  因此该命令**只发极少量元数据请求（Content-Range 取压缩比），不产生任何 `data/epoch_*.npz`**，可以作为离线体检。
- 因为没有探针样本也没有校准表记录（干净目录里 `cache/calibration.json` 不存在），区间按设计回退到
  `estimate.time_range = [0.8, 1.3]`；这与 `docs/throughput-and-gates.md` 描述的行为一致。

## 4) 绝对路径残留检查

在解压目录内检索 `C:\Users`、`temp_2026`、`trae-cn`、`yufag`、`robocopy`：代码、配置、文档、脚本中均为 **0 命中**。
唯一以 `runs/...` 形式出现的是历史运行目录的相对引用（数据出处说明），不构成运行依赖；`runs/` 本身不在包内。

## 结论

换目录后可正常导入、`--version`、全量单测、离线 estimate，全部退出码 0；无本机绝对路径依赖。
